# run800 — Telegram-бот ЮБ800

Бот для записи в Сборную ЮБ800. Работает на VPS отдельным процессом, без webhook и открытого порта, через long polling.

Имя бота — `run800`, username — `@run800_bot`.

## Логика

Максимально короткий вход:

1. Человек сканирует QR на сайте и открывает `@run800_bot` с `start=site`.
2. Нажимает `/start`.
3. Получает приветственную карточку с кнопкой **«ЗАПИСАТЬСЯ В СБОРНУЮ»**.
4. Следом приходит второе сообщение — приглушённая карточка ближайшей открытой тренировки с кнопкой **«Ближайшая открытая тренировка»**.
5. «Записаться» — имя → согласие → заявка в CRM.
6. После принятия заявки появляются кнопки «Ближайшая открытая тренировка», «Чат участников Сборной» и «Канал о беге».

Телефон и почта не запрашиваются. Для связи используется Telegram ID и username.

## Что происходит с заявкой

- Имя и согласие сохраняются локально в `data/leads.ndjson`.
- Заявка уходит в CRM: `POST /api/leads`.
- Менеджер получает сообщение в staff-группу, тема «Заявки».
- Пользователь получает подтверждение и ссылку на чат.

## Команды

Публичное меню:

- `/join` — записаться в Сборную
- `/event` — ближайшая открытая тренировка
- `/chat` — чат участников Сборной
- `/channel` — канал о беге

`/start` и `/help` работают, но в меню не выводятся. Под приветствием — две кнопки: запись и открытая тренировка; чат и канал появляются там после принятой заявки, но остаются доступны из меню.

Служебное:

- `/cancel` — сбрасывает текущую заявку

## Переменные окружения

```env
BOT_TOKEN=...
MANAGER_CHAT_ID=-1003939653342
MANAGER_THREAD_ID=4
STAFF_CHAT_ID=-1003939653342
CHANNEL_URL=https://t.me/yb800run
CHAT_URL=https://t.me/yb800club
CRM_INTAKE_URL=http://127.0.0.1:4174/api/leads
PRIVACY_URL=https://run800.ru/privacy.html
DATA_DIR=./data
```

- `MANAGER_CHAT_ID` — staff-группа «ЮБ800 — Команда».
- `MANAGER_THREAD_ID` — тема «Заявки».
- `STAFF_CHAT_ID` — та же staff-группа для служебных команд.
- `CRM_INTAKE_URL` — локальный intake на VPS.
- `CHAT_URL` — публичная ссылка на чат команды. Бот не добавляет в чат автоматически: он присылает ссылку.

Заявки в CRM отправляются с `notify: false`: уведомление менеджеру отправляет бот, чтобы не было дублей.

## Локальный запуск

```bash
cd bot
npm install
node --env-file=.env index.js
```

Если версия Node не поддерживает `--env-file`:

```bash
set -a
source .env
set +a
node index.js
```

Не запускать локально с production-токеном: два long-polling процесса будут забирать обновления друг у друга.

Тесты:

```bash
cd bot
npm test
```

## Деплой на VPS

```bash
cd bot
npm install --omit=dev
sudo rsync -a --delete \
  --exclude .env --exclude data --exclude node_modules \
  ./ /opt/yb800-bot/
sudo rsync -a node_modules/ /opt/yb800-bot/node_modules/
sudo chown -R yb800bot:yb800bot /opt/yb800-bot
sudo chmod 600 /opt/yb800-bot/.env
sudo systemctl restart yb800-bot
```

Проверка:

```bash
systemctl is-active yb800-bot
journalctl -u yb800-bot -n 20 --no-pager
```

## Проверка сценариев

1. QR → `/start` → видны «Записаться в Сборную» и «Открыть чат».
2. «Открыть чат» → открывается чат, заявка не создаётся.
3. «Записаться» → имя → согласие → заявка в CRM.
4. Проверить заявку в `/opt/run800-crm/data/leads.ndjson`.
5. Проверить сообщение в теме «Заявки» staff-группы.
6. Повторное нажатие «Согласен» не создаёт дубль.
7. `/chat` — ссылки на канал и чат.
8. `/id` в staff-группе — `chat_id`.

## Безопасность

- `.env` и `data/` не коммитить.
- Токен и chat_id не публиковать.
- В логи не писать имена и контакты.
- Медицинские данные и данные карт — не в Telegram, только в CRM.
- При утечке токена — `/revoke` в BotFather и новый токен.
