# run800 — Telegram-бот ЮБ800

Бот для клуба Юрия Борзаковского. Работает на VPS отдельным процессом, без webhook и открытого порта. Использует long polling Telegram Bot API.

Имя бота — `run800`, username — `@run800_bot`.

## Логика

Максимально короткий вход:

1. `/start` — главное меню.
2. «Записаться на открытую тренировку» — имя, согласие, QR-пропуск. Контакт не нужен.
3. «Форматы и цены» — пробная, клуб, персональная. Для платных форматов контакт обязателен.
4. «Чат и знания» — ссылки на публичный канал и публичный чат клуба.

Нет выбора «первый километр / личный рекорд»: уровень тренер определяет на первой тренировке.

### Открытая тренировка

- имя;
- согласие;
- бот выдаёт персональный пропуск `YB800-XXXXXXXX` и QR-картинку;
- заявка уходит в CRM и в тему «Заявки» staff-группы;
- контакт не запрашивается.

### Платные форматы

- имя;
- телефон, email или `@username` — обязательно;
- согласие;
- проверка заявки;
- заявка уходит в CRM и в тему «Заявки» staff-группы;
- оплата — вручную через менеджера.

## Команды

Публичное меню:

- `/start` — главное меню
- `/chat` — канал и чат
- `/help` — как работает бот

Служебное:

- `/id` — показать `chat_id`; доступно в staff-группе и личке, в публичном меню не показывается
- `/cancel` — скрытая команда, сбрасывает текущую заявку; в меню и `/help` её нет

## Переменные окружения

```env
BOT_TOKEN=...
MANAGER_CHAT_ID=-1003939653342
MANAGER_THREAD_ID=4
STAFF_CHAT_ID=-1003939653342
CHANNEL_URL=https://t.me/yb800run
CHAT_URL=https://t.me/yb800club
CRM_INTAKE_URL=http://127.0.0.1:4174/api/leads
PRIVACY_URL=https://run800.ru/privacy.html
DATA_DIR=./data
```

- `MANAGER_CHAT_ID` — staff-группа «ЮБ800 — Команда».
- `MANAGER_THREAD_ID` — тема «Заявки» (сейчас `4`).
- `STAFF_CHAT_ID` — та же staff-группа, для служебных команд.
- `CRM_INTAKE_URL` — локальный intake на VPS.
- `CHANNEL_URL`, `CHAT_URL` — публичные ссылки.

Заявки в CRM отправляются с `notify: false`: уведомление менеджеру отправляет сам бот в тему «Заявки», чтобы не было дублей.

## QR-пропуск

- Пропуск: `YB800-XXXXXXXX`.
- QR содержит этот код.
- Менеджер сканирует QR и сверяет код со списком заявок.
- Зависимость: `qrcode` (PNG-буфер, отправляется через `sendPhoto`).

## Локальный запуск

```bash
cd bot
npm install
node --env-file=.env index.js
```

Если версия Node не поддерживает `--env-file`:

```bash
set -a
source .env
set +a
node index.js
```

Тесты:

```bash
cd bot
npm test
```

## Деплой на VPS

```bash
cd bot
npm install --omit=dev
sudo rsync -a --delete \
  --exclude .env --exclude data --exclude node_modules \
  ./ /opt/yb800-bot/
sudo rsync -a node_modules/ /opt/yb800-bot/node_modules/
sudo chown -R yb800bot:yb800bot /opt/yb800-bot
sudo chmod 600 /opt/yb800-bot/.env
sudo systemctl restart yb800-bot
```

Проверка:

```bash
systemctl is-active yb800-bot
journalctl -u yb800-bot -n 20 --no-pager
```

## Проверка сценариев

1. `/start` → «Записаться на открытую тренировку» → имя → согласие → QR-пропуск.
2. `/start` → «Форматы и цены» → «Клуб» → имя → контакт → согласие → проверка → отправка.
3. Платный формат без контакта не должен отправляться.
4. Проверить заявку в `/opt/run800-crm/data/leads.ndjson`.
5. Проверить сообщение в теме «Заявки» staff-группы.
6. `/chat` — ссылки на канал и группу.
7. `/id` в staff-группе — `chat_id`.

## Безопасность

- `.env` и `data/` не коммитить.
- Токен и chat_id не публиковать.
- В логи не писать имена и контакты.
- Медицинские данные и данные карт — не в Telegram, только в CRM.
- При утечке токена — `/revoke` в BotFather и новый токен.
