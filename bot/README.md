# ЮБ800 — Telegram-бот

Бот для клуба Юрия Борзаковского. Работает на VPS отдельным процессом, без webhook и без открытого порта. Использует long polling Telegram Bot API.

Текущий статус: бот создан и задеплоен на VPS как `yb800-bot`, username `@YB800_bot`. Сервис активен. `MANAGER_CHAT_ID` настроен; тестовое сообщение менеджеру отправлено. На сайте Telegram — один из каналов: ссылка и QR в карточке блока «Вступить в клуб»; основные CTA открывают форму.

## Что умеет

- `/start` — знакомство и выбор пути: «Первый километр» или «Личный рекорд».
- Выбор формата: открытая пробежка, пробная неделя, клуб, премиум, персональная тренировка.
- Сбор имени и телефона/Telegram.
- Отдельное согласие на обработку данных со ссылкой на политику.
- Проверка заявки перед отправкой.
- Уведомление менеджеру в Telegram.
- Сохранение заявки в `data/leads.ndjson`.
- `/cancel` — отменить текущую заявку.
- `/id` — показать `chat_id` для настройки менеджерского чата.
- `/help` — краткая справка.

## Требования

- Node.js 18 или новее.
- Отдельный токен бота от @BotFather.
- Отдельный systemd-сервис. Текущий бот на VPS не затрагивается.

Внешние npm-зависимости не нужны.

## 1. Создать бота

1. Откройте @BotFather.
2. `/newbot`.
3. Имя: `ЮБ800` или `YB800 Club`.
4. Username: `YB800_bot` уже занят этим ботом.
5. Сохранить токен в менеджере секретов.

Ссылка в карточке Telegram-бота и QR уже обновлены под `https://t.me/YB800_bot?start=site`.

## 2. Настроить менеджерский чат

1. Создайте группу «ЮБ800 — заявки».
2. Добавьте бота в группу.
3. Напишите в группу `/id`.
4. Скопируйте отрицательный `chat_id` группы.

Можно использовать и личный чат с ботом, но группа надёжнее: заявки не теряются в переписке.

## 3. Переменные окружения

Создайте `.env` по образцу `.env.example`:

```
BOT_TOKEN=123456789:токен
MANAGER_CHAT_ID=-1001234567890
PRIVACY_URL=https://run800.ru/privacy.html
DATA_DIR=./data
```

`MANAGER_CHAT_ID` можно оставить пустым на первом запуске: бот будет сохранять заявки, но не отправлять их менеджеру.

Права:

```bash
chmod 600 .env
chmod 700 data
```

## 4. Локальный запуск

```bash
cd bot
node --env-file=.env index.js
```

Если версия Node не поддерживает `--env-file`:

```bash
set -a
source .env
set +a
node index.js
```

Проверка логики без Telegram:

```bash
cd bot
node --test
```

## 5. Запуск на VPS через systemd

Рекомендуемая папка: `/opt/yb800-bot`.

```bash
sudo useradd --system --home /opt/yb800-bot --shell /usr/sbin/nologin yb800bot
sudo mkdir -p /opt/yb800-bot
sudo cp -R bot/. /opt/yb800-bot/
sudo cp /opt/yb800-bot/.env.example /opt/yb800-bot/.env
sudo nano /opt/yb800-bot/.env
sudo chown -R yb800bot:yb800bot /opt/yb800-bot
sudo chmod 600 /opt/yb800-bot/.env
sudo chmod 700 /opt/yb800-bot/data
sudo cp /opt/yb800-bot/systemd/yb800-bot.service /etc/systemd/system/yb800-bot.service
sudo systemctl daemon-reload
sudo systemctl enable --now yb800-bot
sudo systemctl status yb800-bot
```

Логи:

```bash
sudo journalctl -u yb800-bot -f
```

Если пользователь `yb800bot` уже есть или используется другой пользователь — измените `User` и `Group` в service-файле. Не запускайте второй экземпляр с тем же токеном: Telegram вернёт конфликт polling.

## 6. Обновить сайт

После смены бота или username:

1. Заменить `https://t.me/YB800_bot?start=site` в карточке Telegram-бота в `landing/index.html`.
2. Пересобрать `landing/assets/telegram-qr.svg` под новый URL.
3. Проверить, что карточка и QR открывают одного бота.
4. Проверить, что основные CTA открывают форму, а не Telegram.
5. Проверить, что в боте открывается меню, а не пустой чат.

## 7. Проверить сценарий

1. `/start` → «Первый километр» → «Открытая пробежка».
2. Ввести имя и телефон.
3. Поставить согласие.
4. Проверить заявку и отправить.
5. Убедиться, что сообщение пришло в менеджерскую группу.
6. Проверить `data/leads.ndjson`.
7. Повторить для «Личный рекорд» и другого формата.
8. Проверить `/cancel` и `/start` посреди сценария.

## 8. Данные и безопасность

- Заявки хранятся в `data/leads.ndjson`; файл и папка доступны только пользователю бота.
- В логах нет имени и контакта; логируется только ID заявки и ошибки.
- Токен и chat_id не коммитить.
- Не отправлять токен в чат.
- При утечке — `/revoke` в BotFather и новый токен.
- Политику ПДн согласовать с юристом до публичного запуска.

## 9. Ограничения

- Нет оплаты: бот собирает заявку, оплата — вручную или позже.
- Нет базы данных: только NDJSON-файл. Для роста до сотен заявок можно перейти на SQLite/Postgres.
- Нет deep links: выбран один общий вход, сценарий выбирается в боте.
- Нет аналитики переходов из бота в CRM.
